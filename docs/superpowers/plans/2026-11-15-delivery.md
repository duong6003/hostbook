# UI, module and CI delivery plan

> Agentic workers: use subagent-driven-development or executing-plans task by task. Keep this plan and ../progress/delivery.md current after every task.

Goal: deliver the approved remaining UI proposals on main's screen kit, extract maintainable modules without performance regression, and improve CI efficiency and platform coverage.
Architecture: explicit Bash module loading, existing ui_* helpers and vi/en strings. No automatic lazy-load framework or new production runtime dependency. Code and fixtures remain Bash 3.2-compatible.
Spec: ../../design/ui-migration.md; ../../design/module-loading.md; ../../design/screens.md; ../../../AGENTS.md.

## Constraints

- Main baseline ef847ee; work only in task worktrees. Preserve personal host/vault/SSH/keychain data; use isolated HOME/config/state fixtures.
- Preserve classic host search and existing validation, undo HEAD guard, PROD safeguards, editor/password workflows and language/theme support.
- Performance budgets and measurement requirements in AGENTS.md apply. Compare existing, extracted-eager and selective loading with the same fixture; a framework requires evidence, not preference.
- User approved execution, model delegation and local commits. Prepare reviewable changes and test evidence; no direct push/merge to main. A draft feature PR for CI verification is within the agreed development work.
- Keep CI, mechanical extraction and behavior changes in separate commits. Worktree app changes are sequential; CI has its own worktree.
- Before changing a shared function, inventory callers. Preserve stdout/return-code contracts. Update installers, tests, language and guidance together where affected.

## Review focus

1. Sourced test fixtures and installed callbacks under spaced/Unicode paths must load the correct modules.
2. Import duplicate/rollback/key handling must not overwrite unrelated or uncommitted data.
3. Escape/back/cancel must retain drafts without committing unintended changes.
4. Short terminals, long unbroken values, 30+ hosts and changed language/theme must keep actions accessible.
5. CI cache contents are untrusted until verified; event rules must preserve required PR/main checks and lifecycle coverage.
