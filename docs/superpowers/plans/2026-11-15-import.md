## Global constraints

- Work only in the app worktree; production changes start after module extraction completes. CI owner controls workflows/Windows lifecycle files.
- Isolate HOME, XDG_CONFIG_HOME, HOSTBOOK_DIR, HOSTBOOK_STATE, HOSTBOOK_SSH_CONFIG and file-backed test keychain; never touch personal keys, agent, config or hosts.
- Preserve main's language/theme/screen kit, original key files, credential encryption/fingerprint deduplication, PROD safeguards, editor/password workflows outside import, and undo HEAD guard.
- Standard list/SSH-config import adds only new names; first accepted occurrence wins, existing/repeated names are skipped. Package import retains explicit update/keep/both/replace decisions; do not turn it into add-only import.
- No host write before preflight and credential acceptance. Independently confirmed vault/credential saves may remain after later host cancellation, as approved in `4bd3754`; explain this in key confirmation copy. No claim of all-or-nothing credential rollback.
- Private staging uses `tmpd`; no source/eval of user paths/content. No added work on per-key callbacks, network in previews or automatic SSH checks.

## Review ruling: saved values

The preflight shows the directives that will be saved, rather than simulating arbitrary active SSH configuration. Missing values are labeled as coming from SSH config, and the screen says active settings can override saved values. Package preview generates the same blocks as apply, including any omitted Port or injected ProxyJump. This preserves retained values without evaluating or rewriting the user's unrelated Include tree.

## Review focus

1. Failure after partial writes preserves preexisting dirty/staged/untracked files and original keys.
2. Existing aliases never cause unused key reads/prompts; shared aliases and repeated blocks never create duplicate host names.
3. SSH Include/Match/identity syntax and archive links cannot bypass validation or execute commands during preflight.
4. Escape returns through source/picker/preflight/results without resetting drafts, changing prior results or implicitly opening an editor.
5. 30 hosts, long paths/descriptions and short terminals leave full-list/actions/undo accessible; stale undo never reverts a later change.

## Source findings and minimal interfaces

- Main `apply_change` uses repository-wide `git checkout`/`git clean` on failure. Do **not** use it for imported writes. Old `apply_import_config` covers only `.conf`; packages also write secrets/groups and may alter history through replacement.
- Main `save_and_sync` does not reliably return commit failure (its final flash write can succeed). Import must check `commit_all` explicitly before publishing success; do not mask failure with `unlock`, `flash` or cleanup.
- Main `vault_init` currently invokes migration; old onboarding separated it. Make initialization idempotent and call migration explicitly from onboarding/manual `vault init`, preserving current flows without recursive/repeated migration during key import.
- Keep `import_flow [file]` and `import_done NEW UPDATED SKIPPED`, `ONLY_NEXT` and `$STATE/last-import` contracts. Publish last-import only after successful apply; canceled/failed import retains the prior result file.
- Add/adapt in `lib/import.sh`: `prepare_import_config SPLIT_DIR` -> private staged directory containing `.conf` and `added`; `import_config_keys STAGE` -> status, modifies only staged host blocks plus explicitly confirmed vault saves; `apply_import_config STAGE` -> status; `import_review STAGE SOURCE_LABEL` -> accept/cancel without writes.
- Reuse these small staging/rollback operations for list/package import where needed; no generic transaction/plugin framework. A transaction snapshots an explicit relative-file manifest, whether each path existed, original bytes/modes and the Git index if it will stage. Package manifest includes affected `.conf`, `groups.tsv`, secret files and replacement-related history; reject symlink destinations before mutation.
- Extend `file_pick START HEADER [ENTER] [DOTFILES] [SESSION_DIR]` with optional session storage; existing callers stay compatible. Add `ui_multiline LABEL VALUE` -> text/status in `lib/ui.sh` for native multiline paste entry. No second file picker.

## Explicit limits and blockers

- One key per concrete imported host remains the approved data model. Includes, wildcard/Match credential inheritance and quoted aliases require an explicit corrective error; they must never silently weaken credential handling. Hardware-backed/provider keys are not made exportable by this work.
- Old rollback code is a starting point, not proof of transactional package safety. No apply task is complete until injected partial-write/commit failures demonstrate preservation across its actual file set.
- Read-only OpenSSH config inspection is not inherently side-effect-free when Match exec is present; the pre-parser guard must precede every imported-data path reaching SSH. Archive entry names alone do not rule out link traversal.
- Prototype import is synthetic. Its screenshots establish layout intent, not parsing, vault, transaction or undo correctness. Do not copy old Vietnamese-only UI or replace main's real undo with the prototype confirmation.
