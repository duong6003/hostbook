**Goal:** Extract maintainable UI/import modules without changing behavior or slowing callbacks, then give the remaining UI work explicit boundaries.

### Dependencies and loading contract

- Resolve module directory once as `LIBDIR=${HOSTBOOK_LIB_DIR:-${SELF%/*}/lib}` after `resolve_self`; `SELF` already resolves installed symlinks. Quote every source path and fail nonzero on a missing required module. Do not infer paths from cwd, and do not overload `HOSTBOOK_APP` (the terminal-parent flag).
- `HOSTBOOK_LIB_DIR` is a fixture override analogous to existing `HOSTBOOK_LANG_DIR`. Production defaults need no override. Copied tests must export it, including to child callbacks.
- Source UI at the former screens section; earlier helper references are resolved when called, after definitions load. Remove moved definitions from entrypoint rather than wrapping them. Preserve all UI variable defaults and initialization order.
- First commit sources import eagerly before dispatch, establishing a behavior-equivalent comparison point.
- Selective version replaces only the import source with an explicit decision: sourced library fixtures load import; executed `_import_parse`, `_import_write`, `_import_classify`, `_import_apply`, `_split` load import; other `_...` commands do not; normal commands load import because home calls `clip_offer`, Tools invokes `import_flow`, and first-run invokes `split_config`.
- Detect sourced fixtures with `[ "${BASH_SOURCE[0]}" != "$0" ]`; retain the existing `# ---------- entry point ----------` marker and sed-based fixtures. No new source-only API is needed.
- UI is intentionally shared/eager, including `file_pick`; do not optimize individual helpers without measurement. Keep `apply_theme` and `lang_load` where they run now (immediately before `sweep_tmp` definition and entrypoint); do not move them into feature modules.
- Later hosts/settings modules load for sourced fixtures and human commands, not unrelated `_...` callbacks. Add explicit internal exceptions only if the caller inventory proves one. Keeping preset/demo helpers in core avoids a settings exception for `_demo`.

### Caller inventory to preserve

Import's external callers are dispatch (`_import_*`, `_split`, `import`), `tools` (`import_flow`), `home` (`clip_offer`), and `first_run` (`split_config`). Import reaches shared `parse_addr`, `read_suggest`, `host_block`, `write_host`, `apply_change`, host mutation helpers, vault/secret operations, `check_hosts` and `undo_last`; these remain defined in core. It sets `ONLY_NEXT` and writes `$STATE/last-import` for home/results. Do not change these contracts during the move.

Before moving functions, run `rg -n '\b(function_name|other_name)\b' hostbook tests` for each group and inspect callers, including test stubs. `read_suggest` and `add_*` helpers intentionally mutate caller locals; avoid running them in new subshells.

## Multi-field form feasibility and smallest faithful implementation

The prototype's `framed-input.py` is a curses app with multiple positioned input widgets. Installed local gum 2.0.2 exposes single `input`/`write`, not a form command; fzf exposes one query editor. Neither supplies the prototype's several independently positioned cursors. Copying the Python prototype adds a forbidden runtime dependency. A native Bash terminal form is permitted if necessary, but it must explicitly handle Unicode, paste, resize and signal cleanup; it belongs in the separate form task.

First spike a **single persistent fzf form**: display the complete draft as labeled field rows, and use fzf's query editor for the active text field on that same screen. Tab/Shift-Tab cycles fields; the active row and query label identify what typing changes. Enter on project/login/tags/jump opens the existing compact chooser and returns to the preserved form. Review/Cancel are explicit actions. The spike is acceptable only if it preserves direct editing with Tab/Shift-Tab and all draft fields together inside one outer frame. An edit-one-field menu or wizard does not satisfy the requirement. fzf does not place its cursor directly inside each field row; do not claim this spike matches the approved interaction. If that limitation prevents faithful direct editing, implement the native Bash form in the separate form task, using the same draft/validation contract below. Do not add boxes around individual fields.

- Real draft fields: name, address, user, port, project, login, tags, jump and description. Do not reduce to the prototype's five fields. At 44x24 use compact one-line rows; on shorter terminals scroll the field viewport while keeping input/actions/footer available.
- Add `ui_form DRAFT_DIR` in `lib/ui.sh`, returning success only for Review and status 1 for Cancel. Files under the private `tmpd` directory hold literal values for fixed field IDs; never source/eval user data. `add_host` owns the directory across chooser/review returns. Use a small fixed schema for this actual form, not a form framework.
- Reuse existing validation rules and `parse_addr` for semantic validation. Preserve inference, suggestion provenance and peer-copy behavior; suggestions may fill untouched fields, never overwrite edits when returning from review. Run final validation again before the existing save/rollback code.
- Follow `ui_field`'s generated-small-script pattern for Tab/change callbacks: load no application, use builtins and precomputed translations, commit the active query to its literal-value file and change active field/query/row. Read query through `FZF_QUERY` or fzf-escaped positional placeholders, never concatenate it into shell code. If returning fzf action strings, account for action delimiters in arbitrary description values; prove literal `() + : $()`, quotes and backslashes survive without executing anything.
- Do not invent `focus` callbacks that overwrite the active draft with an old query or create change-query recursion. Serialize small field transitions and refresh only the current draft; no async workers/cache required. Prefer native fzf text editing over per-character shell redraw.
- First write a small real-fzf test of query switching, delimiter-safe values, retained drafts and minimum-version behavior. Local fzf is 0.75; verify against **0.63**, especially any `transform-query`, prompt/label changes and multiline/wrap options, before adopting them. If the floor cannot support an action, use supported fzf actions or a bounded return/reopen on field transitions and measure it; do not quietly raise FZF_MIN.
- TUI acceptance: all nine fields reachable; type accented text and a long unbroken description; edit name/address/user/port; choose then cancel project/login/tag edits; review/back repeatedly; Escape leaves no host file; invalid values remain visible and unsaved; final save uses real `host_block` and validation; resize/terminal close leaves no orphan. Run vi/en, border none/rounded and 44/60/100x24 cases. Password entry stays the existing masked gum helper.
