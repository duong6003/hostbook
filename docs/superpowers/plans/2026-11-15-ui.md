## Global constraints

- Start after the import work; preserve its result/source behavior. Work only in the app worktree and isolated fixtures; coordinate workflow/Windows changes with CI owner.
- All nine real fields remain: name, address, user, port, project, login, tags, jump and description. No wizard, edit-one-field menu, reduced five-field form or per-field boxes substituted for direct editing.
- One outer form frame; typing edits the focused field in place, Tab/Shift-Tab moves focus, values remain visible together. Dropdowns are for choices, not text editing. Review/back/cancel retains the draft without saving a host.
- Reuse validation, suggestion reasons, peer-copy, new-project/login options, masked password entry, theme/language, safe save/rollback and PROD rules. No user text in shell code or unescaped terminal control output.
- No application boot/network/wait per key. Target <=20 ms pointer/field response, <=50 ms synchronous callback, existing preview/demo/version budgets. Keep Windows lifecycle/terminal cleanup and Bash 3.2 compatibility.

## Review focus

1. Tab/Shift-Tab, arrows, Delete, paste and bare Escape work on actual Bash 3.2; no one-second escape delay or leaked escape suffix.
2. Suggestions/peer cloning never overwrite explicit edits when revisiting project/address/review.
3. Short terminals and long unbroken/Unicode values preserve all data and keep actions reachable.
4. Canceling dropdown/checklist/settings leaves original values; empty selections are valid, not mistaken for cancel.
5. Saved opening preferences, one-host behavior and PROD broadcast confirmation survive the mode UI change.

## Task 1: Test-first direct-edit form spike, then keep only the passing implementation

**Files:** new `tests/form.sh` (isolated real-terminal harness), `lib/form.sh` (form-specific rendering/input), entry helper `ui_form` in `lib/ui.sh`; both language files. Prototype files stay unchanged.
**Interface:** `ui_form DRAFT_DIR` edits literal files for fixed IDs `name address user port project login tags jump desc` and preserves `focus`/cursor state. Status 0 writes `action=review|project|login|tags|jump`; status 1 is cancel; unexpected terminal failure is nonzero. This function does not save hosts, choose credentials or launch SSH. `add_host` handles returned choice actions and re-enters the same draft. Call directly, not in command substitution; terminal output goes to `/dev/tty`.

- [ ] Implement the smallest **native Bash** direct-edit spike in `lib/form.sh`: indexed arrays for values/cursors/dirty flags; compact one-line fields at 24 rows; active cursor positioned in that row; render through theme roles/breadcrumb/key helpers. `ui_form` explicitly sources this module on entry so ordinary callbacks do not parse a terminal editor. No form-schema registry or generic widget framework.
- [ ] A fzf experiment is optional only if cheaper: it must pass the exact same cursor-in-field/direct-edit/all-visible tests. A query box above a field list is not accepted merely because data persists. Do not spend the task building both implementations; retain one passing approach.
- [ ] Native implementation saves/restores `stty`, cursor visibility, bracketed-paste/alternate-screen state and original traps on every return/INT/HUP/TERM. Do not replace the application's trap-free parent or swallow cleanup. Save terminal size once and refresh on WINCH; use builtins for ordinary edits/redraws, no `stty/tput/awk` per character.
- [ ] Decode known navigation/delete/Shift-Tab/paste sequences as input, not literal text; support Home/End, Left/Right, Backspace/Delete, Ctrl-U/Ctrl-K, Enter on choices/actions, Ctrl-C/Escape cancel. If this fails, fix the decoder before host integration rather than declaring a wizard equivalent.
- [ ] Assert terminal modes restored after Review, Cancel, dropdown return, process failure and terminal close; use existing process-group `end_ui` teardown.
